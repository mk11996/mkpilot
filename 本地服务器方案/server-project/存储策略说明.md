# 服务器存储策略

当前服务器按文件扩展名执行保留策略：

- `CSV`：驾驶轨迹数据，永久保留。自动清理不会删除 CSV。
- `.ts`、`.hevc`、`.h265`、`.mp4`、`.mkv`、`.webm`：视频数据，共用 80 GiB 上限。超过上限时按最早上传时间删除最旧视频，直到恢复到上限以内。
- 其他已上传文件：作为驾驶日志、错误日志或运行日志，默认保留 60 天，超过后自动删除。

清理任务在 API 启动时执行一次，之后默认每小时执行一次。可通过 Compose 环境变量调整：

```yaml
VIDEO_STORAGE_LIMIT_BYTES: "85899345920"
LOG_RETENTION_DAYS: "60"
CLEANUP_INTERVAL_SECONDS: "3600"
```

管理员可以通过以下接口立即执行一次清理：

```text
POST /api/v1/admin/storage/cleanup
GET  /api/v1/admin/storage
```

两者都需要管理员 Bearer Token。`GET /api/v1/admin/storage` 返回视频、日志、轨迹的数量和占用空间；`POST` 返回本次删除数量。

服务器保留原始 HEVC/TS 文件。网页播放时才生成 MP4 缓存，缓存属于派生数据，删除原始视频时会一并删除对应缓存。

注意：此策略只管理已经通过服务器上传接口登记到数据库的文件。不要直接在 NAS 存储目录内手动放入需要纳入管理的文件；如果直接复制文件，数据库中没有元数据，后台不会显示，也不会参与自动淘汰。
