# 部署后排障说明

## 1. 容器状态

在 Container Station 或终端确认：

```bash
docker compose ps
```

重点看：

- `api` 是否为 `healthy`；
- `postgres` 是否为 `healthy`；
- 容器是否反复重启。

网页后台默认地址：

```text
http://192.168.5.3:18080/admin/
```

如果修改了 `API_PORT`，将 `18080` 替换为实际端口。

## 2. 查看实时日志

```bash
docker compose logs -f api
docker compose logs -f postgres
```

服务端每个请求会记录：

```text
request_id
method
path
status
duration_ms
```

响应头中的 `X-Request-ID` 可用于定位一次请求的完整日志。

## 3. 健康检查

```text
GET /health
```

正常响应：

```json
{
  "status": "ok",
  "database": "ok",
  "storage": "ok"
}
```

如果返回 `503`，优先检查 PostgreSQL 和存储目录权限。

## 4. 诊断接口

需要在 `.env` 设置：

```text
DIAGNOSTICS_TOKEN=一段随机长字符串
```

调用：

```http
GET /internal/diagnostics
X-Diagnostics-Token: 一段随机长字符串
```

该接口会返回：

- 当前服务版本；
- 数据库状态；
- 存储路径；
- 可用存储空间；
- Athena 在线连接数；
- 日志级别。

不要将诊断接口暴露给公网。

## 5. 上传失败排查

按顺序检查：

1. openpilot 是否能访问服务器域名或 IP；
2. `PUBLIC_BASE_URL` 是否是设备可访问的地址；
3. `upload_url` 返回的 URL 是否完整；
4. JWT 的 `identity` 是否与 URL 中的设备 ID 一致；
5. 服务器时间与设备时间是否相差过大；
6. 文件路径是否包含 `..` 或绝对路径；
7. NAS 存储目录是否有写权限；
8. 文件是否超过 `MAX_UPLOAD_BYTES`；
9. 查看 API 日志中的 `upload_url_issued`、`upload_failed` 和 `upload_completed`。

## 6. 数据库问题

```bash
docker compose logs postgres
docker compose restart postgres
```

不要删除 `postgres_data` 卷。删除卷会清空数据库。

## 7. 容器反复重启

```bash
docker inspect --format='{{json .State.Health}}' <api容器名>
docker compose logs --tail=200 api
```

常见原因：

- `.env` 不存在；
- `DATABASE_URL` 密码与 PostgreSQL 密码不一致；
- `STORAGE_ROOT` 没有写权限；
- NAS 端口已被占用；
- 镜像构建或依赖下载失败。

首次部署默认不启动 Caddy。如果启用 HTTPS profile，Caddy 默认使用 `HTTP_PORT=8081` 和 `HTTPS_PORT=8443`，避免占用 QTS 常用端口。

## 8. 当前 MVP 的已知限制

- 上传令牌使用内存集合记录，API 容器重启后旧令牌可能再次可用；
- 注册码使用内存标记，容器重启后会重新可用；
- Athena 目前只有基础 JSON-RPC，不是完整 Connect 兼容实现；
- 当前没有 App 用户登录和管理员权限系统；
- Caddy HTTPS 需要通过 `--profile https` 单独启动；
- HEVC 原始视频通常不能被所有浏览器直接播放，需要后续转码为 MP4/HLS；
- 生产环境必须增加数据库持久化注册码和上传令牌表。
